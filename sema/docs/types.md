# Типы, правила проверки и ограничения (HW3)

Проверка запускается после парсера HW2 (`analyze(program)` в `src/sema.cpp`) и работает только с программой без синтаксических
ошибок. Два прохода: (1) таблица всех функций и формул модуля, (2) проверка тел. Поэтому вызов функции, определённой ниже, — не ошибка.

## Поддерживаемые типы

| Тип | Где встречается |
|---|---|
| `int` | параметры, возвраты, локальные, выражения, индексы, элементы массивов |
| `int[]` | параметры, возвраты, переменные кванторов; **не** локальные (по описанию Funny локальные только `int`) |
| `bool` | только тип условий и предикатов; переменных типа `bool` в Funny нет |
| сигнатура функции | `(int,int[])->(int,int)`; у формулы `(int)->bool`; хранится в таблице модуля, значением выражения не бывает |
| кортеж | результат вызова функции с несколькими `returns`; допустим только справа в кортежном присваивании |
| `error` | служебный: «тип неизвестен из-за уже найденной ошибки». Совместим с любым типом, поэтому одна причина даёт одну диагностику |

`string` в Funny нет, перегрузок нет (имена функций уникальны), неявных приведений нет. Унификация — совпадение типов (`int` с `int`,
`int[]` с `int[]`), `error` совпадает с чем угодно.

## Правила типизации

| Конструкция | Правило |
|---|---|
| число | `int`; допустимо `0..2147483647`; `2147483648` допустимо только прямо под унарным минусом (`-2147483648`) |
| переменная | тип из объявления; должна быть видна (см. области видимости) |
| `-e`, `e1 + e2`, `-`, `*`, `/` | операнды `int`, результат `int` |
| `a[i]` | `a` — переменная типа `int[]`, `i` — `int`; результат `int` |
| `f(e1, ..., en)` | функция существует, это не формула, число и типы аргументов равны сигнатуре; результат — единственный `returns`. Функция с несколькими результатами в выражении — ошибка |
| `length(a)` | встроенная `(int[])->(int)` |
| `e1 == e2`, `!=`, `<`, `<=`, `>`, `>=` | операнды `int`, результат `bool` (массивы не сравниваются) |
| `true`, `false`, `not`, `and`, `or`, `->` | `bool` |
| `forall/exists (v: T \| P)` | `P` — `bool`; результат `bool` |
| `p(e1, ..., en)` в предикате | `p` — формула, число и типы аргументов равны сигнатуре; результат `bool` |
| `x = e;` | `x` — локальная или возврат (не параметр), тип `e` равен типу `x` |
| `a[i] = e;` | `a` — массив-возврат (не параметр), `i` и `e` — `int` |
| `x, y = f(...);` | все цели — локальные/возвраты (не параметры), число целей равно числу `returns`, типы по позициям равны |
| `if`, `while`, `assert`, `assume`, `requires`, `ensures`, `invariant` | условие/предикат типа `bool` |

## Таблицы символов и области видимости

Имена параметров, возвратов и локальных — в одном пространстве имён функции и должны быть уникальны (повтор — ошибка, действует первое
объявление). Функции и формулы — в одном пространстве имён модуля (имена уникальны). Переменные и функции — разные пространства
(вызов всегда со скобками), поэтому переменная может называться как функция.

| Где | Какие переменные видны |
|---|---|
| `requires` | параметры |
| `ensures` | параметры и возвраты |
| тело функции, `invariant`, `assert`, `assume` | параметры, возвраты, локальные |
| тело формулы | параметры формулы |

Переменная, которая есть в функции, но не видна в данном месте (например, локальная в `ensures`), даёт отдельную ошибку «not visible in …»,
а не «unknown variable». Переменная квантора видна только внутри квантора; её имя не должно совпадать с видимой в этом месте
переменной функции и с переменной объемлющего квантора (по описанию Funny). Поэтому `forall (i: int | …)` в `ensures` допустим при
`uses i: int`, а в `invariant` — нет. Параметры только для чтения: присваивание параметру и запись в элемент массива-параметра — ошибки.

«Использование до объявления» в Funny сводится к двум случаям: переменные объявляются в заголовке функции (поэтому ошибка бывает только
из-за области видимости), функции видны во всём модуле (вызов ниже по тексту разрешён, рекурсия тоже).

## Диагностика

Формат: `файл:строка:столбец: error: сообщение`, под ним строка исходника и `^` (как у парсера). Столбцы считаются с 1, в байтах.
Позиция — позиция узла AST; для ошибок в выражениях выбрано то, что точнее указывает на причину: оператор (`+`, `==`, унарный `-`),
имя (переменная, функция, цель присваивания, объявление), начало выражения (несовпадение типа в присваивании, аргументе, индексе).
Проверка не останавливается на первой ошибке; ошибки отсортированы по позиции.

## Ограничения и решения там, где описание Funny молчит

- Проверка идёт только по программе без синтаксических ошибок (парсер возвращает частичное дерево, ошибки по нему были бы ложными).
- Чтение переменной до присваивания не ошибка (по описанию Funny); не проверяется, что все `returns` присвоены.
- Область видимости `assert`/`assume` в описании не названа; приняты все переменные функции (как в `invariant`).
- Вызов функции внутри предиката (`f(x) > 0`) разрешён; одиночный вызов функции как предикат — ошибка, одиночный вызов формулы в выражении или условии — ошибка.
- Диапазон проверяется только у литералов; переполнение при вычислениях и деление на ноль — ошибки времени выполнения, не проверки.
- Одно и то же имя дважды слева в кортежном присваивании (`a, a = f();`) не проверяется.
- **Бонус (вывод типов локальных без аннотации) не реализован.** Грамматика HW2 повторяет описание Funny, где `uses` требует `имя: тип`;
  для опциональной аннотации пришлось бы менять парсер.
