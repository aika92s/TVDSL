# Формат IR и API HW4

## Модель

IR — линейный трёхадресный код по функциям. Операнд имеет один из трёх видов:

- `Immediate`: 32-битная знаковая константа;
- `Variable`: параметр, возвращаемая или локальная переменная Funny;
- `Temporary`: виртуальный регистр `%tN`, созданный генератором.

Имена меток локальны функции. Каждая функция начинается с `entry:` и заканчивается явным `return`. Несколько возвращаемых значений и кортежное присваивание представлены несколькими `dst` одной инструкции `call`. `FunctionIR::types` хранит тип (`int`, `int[]` или внутренний `bool`) каждой переменной и временного, поэтому кодогенератору не требуется снова обращаться к AST.

## Инструкции

| Текст | Поля | Смысл / JVM-ориентированное понижение |
|---|---|---|
| `x = copy a` | `dst[1], args[1]` | перенос значения; `iload/istore` или `aload/astore` |
| `t = neg a` | `dst[1], args[1]` | `ineg` |
| `t = add/sub/mul/div a, b` | `dst[1], args[2]` | `iadd/isub/imul/idiv` |
| `t = eq/ne/lt/le/gt/ge a, b` | `dst[1], args[2]` | сравнение с материализацией `0/1` |
| `t = not/and/or ...` | `dst[1], args[1..2]` | булевы значения представлены `int` 0/1 |
| `t = load a, i` | `dst[1], args[2]` | `iaload` |
| `store a, i, v` | `args[3]` | `iastore` |
| `d... = call f(a...)` | `dst[0..N], args[0..M], name` | вызов; порядок аргументов слева направо |
| `jump L` | `name` | безусловный переход |
| `branch c, T, F` | `args[1], name, alt` | условный переход |
| `assert/assume c` | `args[1]` | проверочная инструкция |
| `return a...` | `args[1..N]` | значения в порядке секции `returns` |
| `L:` | `name` | метка и граница базового блока |

`div` и `load` не удаляются DCE, даже если результат не используется: они могут завершиться исключением. `call`, `store`, переходы, проверки и `return` всегда считаются имеющими побочный эффект.

## CFG

Лидерами блоков считаются первая инструкция, каждая метка и инструкция после терминатора. Последняя инструкция задаёт рёбра:

- `jump L` — одно ребро;
- `branch c, T, F` — два ребра;
- `return` — нет рёбер;
- иначе — переход в следующий блок.

`CFG::blocks` хранит номера инструкций, `successors`, `predecessors`, а после `computeLiveness` — `use`, `def`, `liveIn`, `liveOut`.

## Оптимизации

Все проходы локальны базовому блоку и сохраняют границы исключений/побочные эффекты.

1. Распространение констант заменяет известные операнды и сворачивает арифметику, сравнения и булевы операции. Деление на ноль и `INT_MIN / -1` не сворачиваются.
2. Алгебраические правила: `x+0`, `x-0`, `x*1`, `x*0`, `x/1`; аналогичные правила для `and/or` над 0/1.
3. DCE идёт назад с учётом межблочной живости и удаляет только чистые определения неиспользуемых временных.

## Живость и раскраска

Живость вычисляется до неподвижной точки:

```
liveOut[B] = union(liveIn[S]) для всех S из successors[B]
liveIn[B]  = use[B] union (liveOut[B] - def[B])
```

В графе конфликтов вершины — только временные `%tN`. Ребро добавляется между определяемым временным и всеми живыми после инструкции. Жадная раскраска обходит вершины по убыванию степени (имя разрешает ничью) и выбирает минимальный свободный цвет. Номер цвета — номер виртуального регистра для следующего этапа; `colorCount` задаёт требуемое их число.

## Публичный C++ API

```cpp
ModuleIR generate(const funnyparse::Node&, const funnysema::SemaResult&);
CFG buildCFG(const FunctionIR&);
void computeLiveness(const FunctionIR&, CFG&);
InterferenceGraph buildInterferenceGraph(const FunctionIR&, const CFG&);
void greedyColor(InterferenceGraph&);
FunctionIR optimize(const FunctionIR&, const OptimizationOptions&);
```

Для кодогенератора достаточно последовательно обойти `FunctionIR::code`, сопоставить `%tN` цветам графа, переменные — локальным слотам JVM, а метки — объектам `Label`. Многорезультатный вызов сохраняется одной инструкцией, поэтому следующий этап может выбрать JVM-совместимое соглашение (объект-кортеж или синтетический контейнер) без потери информации.

JSON содержит массив `functions`; у инструкции всегда есть `op`, а непустые поля `dst`, `args`, `name`, `alt` выводятся явно. Числовые операнды остаются JSON-числами, имена — строками.
