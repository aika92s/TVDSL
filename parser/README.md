# HW2 — парсер Funny (LL(1), рекурсивный спуск)

```
исходник -> Lexer (HW1, папка ../lexer: ДКА из ../lexer/data/tokens.txt) -> токены с позициями -> parser.cpp -> AST + диагностика
```

## Сборка и запуск

```sh
cd parser                                # все команды — из папки parser/ (или из корня: make parser-test)
make test                                # сборка и все тесты парсера, пишет parser/REPORT_HW2.md
make build/funny_parse                   # только CLI
./build/funny_parse prog.fn              # AST деревом с отступами
./build/funny_parse --json  prog.fn      # AST в JSON (с line/col)
./build/funny_parse --sexpr prog.fn      # AST одной строкой
echo 'f() returns r: int ensures true r = 1;' | ./build/funny_parse --sexpr -     # "-" = stdin
echo 'f() returns r: int ensures true r = ;' | ./build/funny_parse -
```

Код возврата: `0` — разбор успешен, `1` — есть ошибки (в stderr), `2` — неверный вызов. Пример ошибки:

```
<stdin>:1:37: error: expected expression, found ';'
    f() returns r: int ensures true r = ;
                                        ^
1 error(s)
```

Лексер лежит в соседней папке `../lexer` и используется только на чтение (исходники `funnylex.*` и `data/tokens.txt`).
Парсер **ничего не пишет в `lexer/`** — ни `REPORT.md`, ни `output/`; всё, что он генерирует (`build/`, `REPORT_HW2.md`), лежит в `parser/`.

## Файлы HW2

| Файл | Что это |
|---|---|
| `src/ast.{hpp,cpp}` | узел AST, вывод: дерево / JSON / S-expression |

| `src/parse_main.cpp` | CLI `funny_parse` |
| `docs/grammar.txt` | финальная грамматика, приоритеты, ассоциативность, дополнения |

## Как устроено

- **Интеграция с лексером.** Токены берутся из `Lexer::tokenize` (HW1), позиция `pos` переводится в строку и столбец
  (`\n`, `\r\n` и одиночный `\r` — перевод строки). Токены `ERR` внутри `//`-комментария выбрасываются (лексер обрывает комментарий на не-ASCII байте), остальные `ERR` превращаются в диагностики
  `unexpected character '@'` и выбрасываются из потока, поэтому разбор продолжается. Последовательность байт `→`
  принимается как импликация.
- **Приоритеты** (от высшего): унарный `-`; `* /`; `+ -`; сравнения; `not`; `and`; `or`; `->` (только в условиях).
  Арифметика, `and`, `or` — влево; `->` — вправо; сравнение не цепляется (`a < b < c` — ошибка).
  `else` относится к ближайшему `if`.
- **Режим паники.** Ошибка — исключение, которое ловится на уровне оператора (внутри блока) или определения
  (верхний уровень). Оператор: пропускаем до `;` (она съедается), `}` или слова-начала оператора. Верхний уровень:
  пропускаем до следующего `имя(` после конца определения вне фигурных скобок. Каждый цикл восстановления
  обязан сдвинуть позицию, поэтому парсер не зацикливается; глубина вложенности ограничена 200.
- **Ссылки на формулы.** В `predicate` одиночный вызов `p(x)` без сравнения — `FormulaRef`; в `condition` и
  выражениях вызов остаётся `Call`; формула это или функция, решает семантический этап.
- Грамматика соответствует описанию Funny; дополнения (`assert`/`assume`, пустая программа — ошибка) и то, что парсер
  НЕ проверяет, — в конце `docs/grammar.txt`. Импликация только в условиях (`if`/`while`), в предикатах её нет;
  после формулы `;` не ставится.

## Тесты

`make test` собирает и запускает `tests/parser_tests.cpp`; в конце прогона пишется `REPORT_HW2.md`
(имя, вид, вход, ожидаемый результат, PASS/FAIL по каждому тесту; другой путь — `FUNNY_REPORT=путь`, пустая строка — не писать).
Отдельных файлов с данными нет: положительные программы (`kGoodPrograms`) хранятся с ожидаемым AST в виде
S-expression, отрицательные (`kBadPrograms`) — с ожидаемым списком ошибок `строка:столбец: сообщение`.

Виды тестов в отчёте:

- `good` — программа или фрагмент разбирается, AST совпадает с эталоном: приоритеты и ассоциативность, вызовы и массивы,
  условия и предикаты, кванторы и ссылки на формулы, структура функции/формулы/операторов, позиции узлов (в том числе при CRLF),
  форматы вывода (дерево, JSON).
- `bad` — ошибки совпадают с ожидаемыми по тексту и позиции, в том числе восстановление после нескольких ошибок:
  незакрытые `(`, `[`, `{`, лишние `}` и токены после функции, неверные операторы (`=` вместо `==`, `=<`, `r == 1;`),
  цепочка сравнений, пустой ввод и ввод из одних комментариев, нет `returns`, неверный тип, кортежное присваивание без вызова,
  квантор в условии, импликация в предикате, `else` без `if`, `_` в идентификаторе, посторонние символы.
- `robust` — парсер не зацикливается: разбор всех префиксов хороших программ, 4000 случайных мутаций, 6000 случайных
  последовательностей токенов, глубокая вложенность (5000 скобок).

Добавить тест: строка `Err(...)` / `Prog(...)` / `E(...)` в `tests/parser_tests.cpp`; ожидаемый результат пишется руками.

## Ограничения

- Лексер HW1 знает только ASCII: байт >= 128 вне комментария — ошибка `unexpected character`. В комментариях
  кириллица и любые другие символы допустимы: парсер сам возвращает в комментарий остаток строки после первого
  не-ASCII байта (см. п. 8 в `docs/grammar.txt`). Столбцы в сообщениях считаются в байтах.
- Парсер проверяет только синтаксис; семантика (типы, области видимости, неизменяемость параметров) — следующие этапы.
